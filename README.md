# Вернуть доверие

Учебный прототип «светофора условий» на k1o0n.me. Статический интерфейс на GitHub Pages, отдельная функция Node.js 22+ в Appwrite Cloud, анализ через OpenRouter `xiaomi/mimo-v2.6-pro`. Палитра и шрифты из «Возвращение доверия 2.pptx». Никакой базы или собственного VPS не требуется.

## Что умеет

- Принимает публичную HTTPS-ссылку либо 100–20 000 символов текста.
- Читает HTML страницы и до двух ссылок на условия с того же origin. Передаёт модели тексты, а не голую ссылку.
- Показывает четыре категории: оплата/продление, возврат, доступ, ограничения/доплаты. Статусы: риск, внимание, ОК, нет данных.
- Сверяет дословные цитаты с прочитанными источниками. Неподтверждённые пункты заменяет на «Нет данных». Эта проверка не доказывает правильность интерпретации цитаты.
- Не выдаёт придуманную вероятность мошенничества. «ОК» не является оценкой надёжности продавца.
- Пример результата работает без backend и явно обозначен как вымышленный. Ошибки настоящего запроса не подменяются примером.

## Быстрый локальный просмотр

```sh
npm start
```

Открыть http://127.0.0.1:4173. Зависимостей npm нет. Без `.env` доступны интерфейс и пример. Для реального анализа скопировать `.env.example` в `.env`, заполнить ключ и код доступа, перезапустить. Не коммитить `.env`.

```sh
npm test
npm run build
```

`dist/` содержит только клиентские файлы из явного списка, без backend и секретов.

## Appwrite Cloud через GitHub Student Developer Pack

Подключить [Appwrite Education](https://appwrite.io/education). По условиям Pack на момент подготовки: два проекта с лимитами уровня Pro на время участия в студенческой программе. Вызовы OpenRouter оплачиваются отдельно.

1. Создать отдельный проект в Appwrite Cloud и функцию Node.js 22 (или более новый доступный runtime).
2. Подключить этот репозиторий GitHub к функции. Root directory: `backend`, Entrypoint: `appwrite.mjs`, Build command: `npm install --omit=dev`. Зависимостей нет, поэтому сборка минимальна.
3. Установить timeout функции **180 секунд**, включить функцию и активировать deployment.
4. В Variables функции добавить секреты (Secret / Sensitive):
   - `OPENROUTER_API_KEY` — отдельный ключ OpenRouter для проекта с небольшим расходным лимитом.
   - `PROTOTYPE_ACCESS_CODE` — длинный случайный код для участников тестирования. Это не ключ OpenRouter. Сайт запросит его при первой попытке проверки, не сохранит в localStorage и не включит в URL.
5. Обычные переменные функции:
   - `OPENROUTER_MODEL=xiaomi/mimo-v2.6-pro`
   - `ALLOWED_ORIGINS=https://k1o0n.me,https://k1o0n.github.io` (точные origin без завершающего слеша). Добавить `https://www.k1o0n.me`, только если этот домен действительно используется.
6. После изменения переменных создать новый deployment, чтобы они применились. Скопировать публичный URL из Domains функции. Функция обслуживает `GET /health`, `POST /analyze`, `OPTIONS /analyze`; SDK и клиентский Appwrite API key не нужны. Защита платного вызова выполняется кодом доступа внутри функции.
7. Проверить `https://<домен-функции>/health`: `configured` должен быть `true`.

### Деплой через Appwrite CLI (вместо шагов 1–3)

Проект `trust-proj` (`6abb88f6002fbbdbb4c0`, регион Frankfurt). `appwrite.config.json` в корне описывает функцию `trust-analysis`: Node 22, `backend/appwrite.mjs`, timeout 180 с, публичный вызов (`execute: any`). Секреты в конфиг не входят.

```sh
npm install -g appwrite-cli@latest
appwrite login
appwrite client --endpoint="https://fra.cloud.appwrite.io/v1" --project-id="6abb88f6002fbbdbb4c0"
appwrite push functions --function-id trust-analysis
```

Переменные из шагов 4–5 задать в консоли функции (Settings → Environment variables), затем повторить `appwrite push functions`, чтобы новый deployment их подхватил.

Доступность регистрации, программы и выбранного региона Appwrite нужно проверить в своём аккаунте. Старый backend пользователя не используется.

## GitHub Pages

1. В Settings → Pages выбрать Source: **GitHub Actions**.
2. В Settings → Environments → `github-pages` → Variables добавить **`PUBLIC_API_BASE`** с HTTPS-origin функции, например `https://<id>.fra.appwrite.run`. Без `/analyze` и без ключа.
3. Workflow `.github/workflows/pages.yml` проверяет код, собирает только клиентский `dist/` и публикует его. Триггер — push в `main` или ручной запуск. Если основная ветка другая, изменить `branches`.
4. `CNAME` сохраняет домен `k1o0n.me`. Для другого способа публикации можно указать адрес функции в `config.js` вручную вместо GitHub Variable.

**OpenRouter key хранится в Appwrite, не в GitHub Pages.** GitHub Environment Secrets доступны workflow, но не создают сервер. Нельзя вставлять ключ в JS при сборке: он станет доступен посетителям. Для текущего GitHub workflow секрет OpenRouter вообще не нужен.

## Ограничения и защита

- Внешние запросы только по HTTPS к публичным DNS-именам. Заблокированы IP-literal, приватные/резервные DNS-адреса, нестандартные порты, URL с паролем и очевидными токенами. После DNS-проверки HTTPS-соединение закрепляется за проверенным IP; каждый redirect проходит повторную проверку. API key отправляется исключительно OpenRouter.
- Максимум 1,5 MB HTML на страницу, 18 000 символов на источник, до трёх страниц. Сокращение может пропустить условия в конце длинной страницы. HTML извлекается простым текстовым парсером: JavaScript не исполняется, интерактивные checkout, PDF, CAPTCHA и страницы после входа не поддерживаются. Для них нужен режим текста.
- Таймаут сбора 25 секунд и модели 90 секунд. DNS использует системный resolver; его текущий вызов может завершиться позже deadline, после чего загрузка прерывается. Нет повторных платных вызовов автоматически.
- До 5 попыток в минуту на клиентский IP и до 3 одновременных анализов **на экземпляр функции**. Это не глобальная квота Appwrite. Счётчики сбрасываются при холодном старте и не синхронизированы между экземплярами. Код доступа и расходный лимит ключа нужны для прототипа; перед массовым публичным запуском потребуется общая квота/аутентификация.
- Origin/CORS не являются аутентификацией. Без ключа или кода доступа функция закрыта. Код доступа передавать участникам отдельно; не добавлять его в клиентский config или репозиторий.
- Тексты не записываются в базу, код не логирует запросы/ответы/секреты. Платформа и провайдеры имеют собственные политики журналирования. Не отправлять персональные данные.
- Модель может неверно интерпретировать даже реальную цитату, а сайт может публиковать ложные условия. Проверка не заменяет оценку продавца и юридическую консультацию.

## Проверка после подключения

1. На сайте выполнить «Посмотреть пример результата»: должны появиться четыре карточки с отметкой примера.
2. Ввести публичную ссылку, получить запрос кода, ввести `PROTOTYPE_ACCESS_CODE`, повторить. Убедиться, что результат ссылается на реальный источник.
3. Проверить текстовый режим; проверить недоступную ссылку: должна появиться ошибка, а не фиктивный успешный анализ.
4. В Network браузера увидеть только запрос к функции. `Authorization: Bearer …` OpenRouter не должен появляться в браузере.

Тесты `npm test` используют контролируемые ответы модели/сети и проверяют DNS/IP-защиту, redirects, цитаты, ошибки, формат API и лимиты. Они не заменяют реальный вызов MiMo после установки ключа.
